
## Напоминания: причина поломки (08:30 UTC)

- Симптом: задание срабатывало в срок, но сообщение не приходило. В логе Gateway: `Scheduled account "<id>" is unavailable`.
- Причина №1: планировщик пропускает проверку аккаунта **только для имени `default`** (видно в исходниках: `Fn !== "default"`). Аккаунт назывался `psychologist` → проверка шла и падала. Переименован в `default` (токен тот же).
- Причина №2 (главная, осталась после переименования): `sessionTarget: "current"` для cron-прогона умирает с `attempt disposed before transcript write` (112 с и ошибка) — доставка идёт через транскрипт основной сессии и срывается.
- **Рабочая схема:** `sessionTarget: "isolated"` + явный `delivery` (channel/to/accountId). Проверено: `status ok`, `delivered true`, 3.8 с, напоминание дошло.
- Ещё: плагин Telegram был `disabled` в конфиге — включён (`openclaw plugins enable telegram`).
- Уроки записаны в `AGENTS.md`, раздел Automations.

## Напоминания без модели — рабочая схема (08:58 UTC)

- Второй слой поломки: `agentTurn`-задания требуют модель, а DeepSeek отдавал `503 Service is too busy` → прогон падал по idle timeout, доставлять было нечего.
- Решение: `kind: "script"` + `sessionTarget: "isolated"` + `delivery.mode: "none"`, а текст отправляет сам скрипт:
  `await message({ action: 'send', channel: 'telegram', accountId: 'default', target: 'telegram:438449705', message: '...' }); return { sent: true };`
- Грабли: скрипт обязан вернуть объект (`must return an object`), а его собственный вывод планировщик глушит с `deliverySuppressionReason: "empty"` — ни `message`, ни `summary` в возврате не отправляются.
- Проверено: прогон 395 мс, в логе `outbound send ok ... messageId=442`.
